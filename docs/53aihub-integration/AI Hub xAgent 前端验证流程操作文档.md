## 2. Console 管理后台配置（一次性操作）

> **目的**：在 Console 中完成 xAgent 的 Provider、Channel 和 Agent 配置，使前端对话页面可用。

### 2.1 登录 Console

1. 打开浏览器访问 `http://localhost:3000/console`
2. 进入登录页（页面左侧显示品牌装饰图，右侧为登录表单）
3. 选择 **"密码登录"** 标签
4. 输入用户名 `admin`、密码 `admin123456`
5. 点击 **"登录"** 按钮
6. 登录成功后进入 Console 首页仪表盘

### 2.2 配置平台模型（Platform Provider）

xAgent 作为一个大模型调度平台，需要先在 Console 中注册为平台提供商。

1. 在左侧菜单栏找到 **"Site Config"** → 点击 **"Platform Models"**
2. 页面展示已授权的平台卡片列表，确认 **xAgent** 卡片已出现
3. 如果不存在，点击 **"Add Provider"** 按钮：
   - Provider 名称：`xAgent`
   - Provider 类型：`xAgent` (对应 type=7)
   - 点击保存

> **后台对应**：`INSERT INTO providers (name, provider_type, config, status, eid) VALUES ('xAgent', 7, '{}', 1, 1);`

### 2.3 配置渠道（Channel）

1. 在 Platform Models 页面，找到 xAgent 平台卡片
2. 点击进入模型列表，确认 xAgent 渠道已存在
3. 渠道信息：
   - 渠道类型：`xAgent Channel`（对应 type=1012）
   - Base URL：`http://localhost:80/`（指向 xAgent 的 Nginx 地址）
   - 鉴权 Key：xAgent 用户的 JWT Token

> **后台对应**：`INSERT INTO channels (type, name, base_url, key, model_type, status, eid) VALUES (1012, 'xAgent Channel', 'http://localhost:80/', '<JWT>', 1, 1, 1);`

### 2.4 创建 Agent

1. 在左侧菜单栏找到 **"App Management"** → 点击 **"Agent"**
2. 进入 Agent 管理列表页（表格视图，支持按分组/平台/类型筛选）
3. 点击页面右上角 **"Create Agent"** 按钮
4. 进入 Agent 创建页面，填写以下内容：

| 字段 | 填写内容 | 说明 |
| --- | --- | --- |
| Agent 名称 | `xAgent Agent` | 在前端 Agent 列表中展示的名称 |
| Logo | 上传或选择默认图标 | Agent 头像 |
| 描述 | `智能对话助手，可调用教学/销售/求职/教研工具` | 简短介绍 |
| Channel 类型 | `xAgent Channel` (1012) | 绑定 xAgent 渠道 |
| 模型 | `xagent-chat` | 通过 model 路由到 xAgent 渠道 |
| Prompt | `You are a helpful AI assistant integrated with 53AIHub...` | System prompt |
| 用户分组 | 全部用户（或选择测试用户组） | 控制谁能使用此 Agent |
| 启用状态 | ✅ 启用 | Agent 创建后立即可用 |

5. 点击 **"保存"** 按钮

> **关键字段说明**：
> - `custom_config` 中存储 `{"xagent_agent_id": 1}`，指向 xAgent 中的 Agent Builder Agent ID
> - `channel_type=1012` + `model=xagent-chat` 确保请求路由到 xAgent 渠道

### 2.5 验证 Agent 出现在列表中

1. 保存后自动返回 Agent 列表页
2. 在表格中确认新创建的 **"xAgent Agent"** 已出现
3. 确认状态为 **"已启用"**

## 3. 前端用户端 — 对话页面操作指南

> **说明**：53AIHub 前端有两种模式：
> - **Desktop 模式**（`/chat`）：左侧侧边栏 + 右侧对话区，适合桌面使用
> - **Website 模式**（`/index/chat`）：全宽页面 + 顶部导航，适合嵌入官网
>
> 两种模式的核心对话操作一致，本文档以 **Desktop 模式** 为例。

### 3.1 页面布局说明

打开 `http://localhost:3000`，登录后进入主界面：

```
┌──────────────┬──────────────────────────────────────┐
│  侧边栏       │         对话主区域                     │
│  (Sider)     │                                      │

│  🔍 搜索      │  │  Agent 名称 / 会话标题          │  │
│              │  ├────────────────────────────────┤  │
│  📌 常用Agent │  │                                │  │
│  - Agent A   │  │  💬 对话消息区域                 │  │
│  - Agent B   │  │  (x-bubble-list)               │  │
│              │  │                                │  │
│  📁 导航菜单   │  │  用户气泡 (x-bubble-user)       │  │
│  - Agent列表  │  │  AI 气泡 (x-bubble-assistant)   │  │
│  - 提示词库   │  │  ...支持流式输出...              │  │

│  - 昨天       │                                      │

│              │                                      │
│  👤 用户信息   │                                      │
└──────────────┴──────────────────────────────────────┘
```

### 3.2 核心 UI 组件说明

| 组件 | 位置 | 功能 |
| --- | --- | --- |
| **侧边栏 (Sider)** | 页面左侧 | 搜索、常用 Agent、导航菜单、对话历史列表、用户信息 |
| **Agent 列表** | `/agent` 页面 | 卡片网格展示所有可用 Agent，点击进入对话 |
| **对话消息列表** (`x-bubble-list`) | 对话区中部 | 滚动显示用户问题和 AI 回复，支持流式加载动画 |
| **用户气泡** (`x-bubble-user`) | 消息列表中 | 显示用户发送的消息，带复制按钮 |
| **AI 气泡** (`x-bubble-assistant`) | 消息列表中 | 显示 AI 回复，支持流式打字效果、推理过程折叠、复制/分享/重新生成 |
| **消息输入框** (`x-sender`) | 对话区底部 | 文本输入、文件上传、Agent 选择、新建对话 |
| **欢迎区** | 新对话时显示 | Agent 介绍卡片、开场白、推荐问题快捷按钮 |

### 3.3 对话操作流程

#### 3.3.1 从 Agent 列表开始对话

1. 点击侧边栏中的 **"Agent列表"**（或访问 `http://localhost:3000/agent`）
2. 页面展示 Agent 卡片网格，每个卡片包含 Logo、名称、简介、对话次数
3. 找到 **"xAgent Agent"** 卡片
4. 点击卡片 → 自动跳转到对话页面 `http://localhost:3000/chat?agent_id=1`
5. 对话页上方显示 Agent 名称，中央显示欢迎信息和建议问题

#### 3.3.2 从侧边栏快捷启动

1. 在侧边栏顶部的 **搜索框** 中搜索 "xAgent"
2. 在搜索结果中找到 **"xAgent Agent"**
3. 点击 Agent 名称 → 自动创建新对话并跳转
4. 或者点击侧边栏 **"常用 Agent"** 区域中已固定的 xAgent Agent

#### 3.3.3 从对话历史恢复

1. 侧边栏下方 **"历史对话"** 区域按时间分组（今天/昨天/7天前/更早）
2. 找到之前的验证对话，点击标题
3. 对话区自动加载历史消息，可继续发送新消息

## 4. 流程一：销售转化流（P3-01）

### 4.1 业务场景

> 销售顾问需要查询 CRM 中的潜在客户线索，获取联系人、来源、意向阶段和预算信息。

### 4.2 页面操作步骤

#### 第 1 步：进入 Agent 对话

1. 打开 `http://localhost:3000`，登录后进入主界面
2. 点击侧边栏 **"Agent列表"**，找到 **"xAgent Agent"** 卡片并点击
3. 进入 `/chat?agent_id=1` 对话页面
4. 确认页面顶部显示 **"xAgent Agent"**

#### 第 2 步：发送 CRM 线索查询

1. 在页面底部的输入框（`x-sender`）中输入：

   ```
   请帮我查询CRM中的销售线索，包括联系人、来源、状态和预计成交金额
   ```

2. 点击发送按钮（或按 Enter 键）
3. 输入框上方出现 **用户气泡**（`x-bubble-user`），显示刚才发送的消息
4. 用户气泡下方出现 **AI 气泡**（`x-bubble-assistant`），显示加载动画

#### 第 3 步：观察流式响应

1. AI 气泡中出现 **流式打字效果**，内容逐字出现
2. 等待响应完成（约 2-5 分钟，复杂任务可能更长）
3. 流式输出过程中可能出现 **"思考中…"** 或 **推理过程折叠区域**
4. 响应完成后，AI 气泡底部出现操作按钮：复制、重新生成、分享

#### 第 4 步：验证响应内容

仔细阅读 AI 回复内容，确认包含以下关键字段（在聊天内容中逐条检查）：

| 验收项 | 应出现的内容 |
| --- | --- |
| 线索 ID | `L001` 或类似的线索编号 |
| 线索来源 | "官网" / "Official Website" |
| 当前阶段 | "初次沟通" / "Initial Communication" |
| 负责销售 | "销售顾问 A" 或具体人名 |
| 预估预算 | 金额范围（如 15000-20000） |
| 意向方向 | "Java" / "后端开发" |

**验收截图**：截取完整的对话页面，确保用户问题和 AI 回复均可见。

#### 第 5 步：追问成功案例（进阶）

1. 在对话页底部输入框中继续输入：

   ```
   这条线索有没有类似的成功转化案例可以参考？
   ```

2. 点击发送
3. 观察 AI 回复中是否出现 **"成功案例"** 相关内容

### 4.3 验收通过标准

- [ ] Agent 卡片在 Agent 列表页正常展示
- [ ] 点击 Agent 后成功进入对话页面
- [ ] 输入消息后，AI 气泡中出现流式响应
- [ ] 响应中包含 CRM 线索的关键业务字段（ID、来源、阶段、预算）
- [ ] 回复格式可读，结构化呈现
- [ ] 追问后 Agent 能理解上下文并给出关联回复

## 5. 流程二：教学管理流（P3-02）

### 5.1 业务场景

> 教学主管需要评估学员提交的 Spring Boot 作业，获取自动化评分和各维度分析。

### 5.2 页面操作步骤

#### 第 1 步：新建对话

1. 在对话页面，点击输入框旁 **"+ 新建对话"** 按钮（或从侧边栏点击 xAgent Agent 创建新对话）
2. 确认对话区域清空，显示 Agent 欢迎信息

#### 第 2 步：发起作业评估

1. 在底部输入框中输入：

   ```
   请帮我评估一份学员的Spring Boot项目作业，从代码结构、算法实现、
   异常处理、代码规范、数据库操作五个维度进行评分和弱点分析。
   ```

2. 点击发送
3. 等待 AI 响应（约 2-5 分钟）

#### 第 3 步：验证评分结果

阅读 AI 回复，确认包含以下内容：

| 验收项 | 应出现的内容 |
| --- | --- |
| 综合评分 | 数值分数 /100（如 85/100） |
| 评分维度 | 代码结构、算法实现、异常处理、代码规范、数据库操作 |
| 各维度得分 | 每个维度有独立分数（如 代码结构: 9/10） |
| 弱点分析 | 至少 2 项弱点，每项标注严重程度（高/中/低） |
| 改进建议 | 每项弱点对应具体改进方法 |

**示例验收片段**：
```
综合得分：85/100

评分明细：
- 代码结构：9/10（模块划分合理）
- 算法实现：8/10（核心逻辑正确，可优化）
- 异常处理：6/10（缺少边界条件处理）
- 代码规范：9/10（命名规范，注释完整）
- 数据库操作：7/10（存在N+1查询问题）

弱点分析：
1. 数据库N+1查询 [严重程度: 高]
   建议：使用JOIN或批量查询替代循环内查询
2. 异常处理不足 [严重程度: 中]
   建议：增加空值和网络异常防护
```

### 5.3 验收通过标准

- [ ] 作业评估结果包含 5 个维度的独立评分
- [ ] 存在弱点分析且每项有严重程度标注
- [ ] 改进建议与弱点一一对应
- [ ] 整体回复格式清晰，易于教学主管决策

## 6. 流程三：求职出口流（P3-03）

### 6.1 业务场景

> 求职顾问需要为 Java 学员制定职业发展规划，查询匹配岗位，并分析岗位要求。

### 6.2 页面操作步骤

#### 第 1 步：新建对话

1. 点击 **"+ 新建对话"** 创建新会话
2. 或从侧边栏点击 xAgent Agent

#### 第 2 步：制定职业规划

1. 在输入框中输入：

   ```
   请为一位有2年Java开发经验的求职者制定职业发展规划，
   包括短期(3-6月)、中期(6-12月)、长期(1-2年)的目标和学习路径。
   ```

2. 点击发送，等待响应

#### 第 3 步：验证职业规划

阅读 AI 回复，确认包含：

| 验收项 | 应出现的内容 |
| --- | --- |
| 短期目标 | 3-6 个月的具体学习/工作目标 |
| 中期目标 | 6-12 个月的目标 |
| 长期目标 | 1-2 年的职业方向 |
| 目标岗位 | 如 "Java 后端开发工程师" |
| 匹配度 | 百分比或评级 |
| 薪资范围 | 具体金额范围 |
| 学习路径 | 从基础到进阶的技能列表 |

#### 第 4 步：查询匹配岗位（进阶）

1. 在同一个对话中继续输入：

   ```
   根据上面的职业规划，帮我查一下有哪些匹配的招聘岗位
   ```

2. 点击发送
3. 验证 Agent 能理解上一轮的职业规划内容，给出匹配的岗位推荐

### 6.3 验收通过标准

- [ ] 职业规划包含三阶段（短期/中期/长期）
- [ ] 有具体的岗位推荐和匹配度评估
- [ ] 学习路径有层次递进
- [ ] 追问岗位时，Agent 能引用前一轮的职业规划内容

## 8. 流程五：xAgent 动态规划与调度验证（P3-05）

### 8.1 业务场景

> **核心价值验证**：xAgent 作为"动态规划与调度大脑"，面对复杂的、多步骤的模糊目标时，应能自主拆解任务、生成 DAG 计划、按步骤选择合适的工具执行，并将多步骤结果综合为最终输出。这是区别于单一 Agent 直接回复的关键能力。

验证场景：销售人员输入一条含简历的新线索，需同时完成"简历解析 → 职业规划 → 岗位匹配 → 销售预案"的全链路自动化。这一场景对应设计文档中的销售转化流（P3-01），但重点验证**规划过程可见性**和**跨工具调度**，而非仅验证最终结果。

### 8.2 页面操作步骤

#### 第 1 步：新建对话

1. 点击侧边栏 **"Agent列表"**，找到 **"xAgent Agent"** 卡片并点击
2. 确认进入 `/chat?agent_id=1` 对话页面
3. 点击 **"+ 新建对话"** 创建新会话

#### 第 2 步：发起复杂模糊任务

1. 在底部输入框中输入一个跨多领域的综合任务：

   ```
   我这边有一条新的销售线索：一位有3年Python开发经验的求职者，
   想转行大数据方向，预算在20000左右。请帮我：
   1. 分析他的背景和转行可行性
   2. 查询当前大数据方向的招聘岗位和热度
   3. 制定一份职业规划
   4. 生成销售首电沟通预案
   ```

2. 点击发送

> **区别于普通对话**：该任务涉及 4 个子目标，需要 xAgent 动态规划步骤并调度不同的工具/Agent 完成。
> - 子目标 1、3 可能需要调用职业规划 Agent（Dify）
> - 子目标 2 可能需要调用岗位分析 Agent（Coze）
> - 子目标 4 可能需要调用销售预案 Agent（Coze）

#### 第 3 步：观察规划阶段

xAgent 收到复杂任务后，应首先进入**规划阶段**（不是直接输出答案）。在 AI 气泡中观察以下行为：

| 验收项 | 应观察到的表现 |
| --- | --- |
| 规划标识 | AI 气泡中出现 **"思考中…"** 或 **"正在规划任务…"** 或推理折叠区域 |
| 步骤拆分 | 输出区域出现 **步骤列表**，将模糊目标拆分为 3 个以上可执行步骤 |
| 步骤描述 | 每个步骤有明确标题（如 "步骤1：分析求职者背景"）和简要说明 |
| 工具选择 | 可观察到步骤间引用了不同工具/Agent（通过工具名称区分） |

**示例规划输出片段**：
```
📋 任务规划：
Step 1: 分析求职者背景 → 调用 [职业规划 Agent]
Step 2: 查询大数据岗位热度 → 调用 [岗位分析 Agent]
Step 3: 制定转行职业规划 → 调用 [职业规划 Agent]
Step 4: 生成销售首电预案 → 调用 [销售预案 Agent]
Step 5: 综合输出 → 汇总以上结果
```

> **注意**：实际规划内容取决于 xAgent 的 Planner 输出格式。关键验收点是**是否产生了多步骤规划**，而非规划的文本格式。

#### 第 4 步：观察逐步执行

在规划阶段之后，xAgent 应**逐步执行**每个步骤。观察以下行为：

| 验收项 | 应观察到的表现 |
| --- | --- |
| 步骤进度 | 可看到当前执行到哪个步骤（如 "正在执行 Step 2/5…"） |
| 工具调用 | 不同步骤调用不同的工具（通过工具名称区分，不应所有步骤调用同一个工具） |
| 中间结果 | 每个步骤执行后展示中间结果摘要 |
| 错误处理 | 若某步骤失败，应有明确的错误提示或降级处理 |

#### 第 5 步：验证最终综合输出

所有步骤执行完毕后，xAgent 应综合各步骤结果生成最终回复。确认以下内容：

| 验收项 | 应出现的内容 |
| --- | --- |
| 背景分析 | Python 3年经验、转行动机、预算20000 |
| 岗位分析 | 大数据方向的具体岗位、热度、薪资范围 |
| 职业规划 | 短期/中期学习路径或转行建议 |
| 销售预案 | 首电沟通要点、话术建议 |
| 结果关联 | 各部分的结论应相互关联（如岗位要求引用了背景分析中的技能缺口） |

**验收截图**：截取完整的对话页面，确保规划阶段、执行过程和最终输出均可见。

#### 第 6 步：对比单 Agent 对话（进阶验证，可选）

为验证 xAgent 的规划调度能力区别于普通 Agent 的直接回复：

1. 切换到普通 Dify/直接模型 Agent（非 xAgent）
2. 发送相同任务
3. 对比两者的回复差异

**期望差异**：
- xAgent：多步骤、分阶段、调用不同工具、有规划过程可见
- 普通 Agent：单次回复、无步骤拆分、无工具切换

### 8.3 验收通过标准

- [ ] xAgent 生成了包含 3 个以上步骤的 DAG 规划
- [ ] 不同步骤调用了不同的工具/Agent（可观察到工具切换）
- [ ] 步骤执行过程可见（进度、中间结果）
- [ ] 最终输出综合了多步骤结果，覆盖了全部子目标
- [ ] 输出内容在不同步骤间有关联性（非简单拼接）
- [ ] 全程在 5 分钟内完成（复杂任务可适当延长）

### 8.4 补充验证场景

以下场景可作为 xAgent 动态规划能力的补充验证（可选执行）：

#### 场景 A：教研全链路（跨多个 Coze 工具）

输入：
```
请帮我为一门"Spring Cloud 微服务实战"课程生成完整的教研内容包：
1. 课程大纲（8个模块）
2. 第一模块的详细教案
3. 第一模块的 PPT 内容
4. 演示代码示例
```

验收点：xAgent 应对以上 4 个子任务生成规划，并顺序/并行调用对应的教研工具（大纲生成 → 教案生成 → PPT 生成 → 代码生成）。

#### 场景 B：求职全链路（跨 Dify + Coze + 自研）

## 11. 常见问题与界面排错

### 11.1 Agent 卡片不显示

**现象**：在 `/agent` 页面找不到 "xAgent Agent"

**检查步骤**：
1. 确认 Console → Agent 管理中该 Agent 状态为 "已启用"
2. 确认 Agent 的用户分组包含当前登录用户
3. 检查 Agent 的 `enable` 字段是否为 `true`

### 11.2 发送消息后无响应

**现象**：点击发送后，AI 气泡一直显示加载动画，没有内容输出

**检查步骤**：
1. 等待 2-5 分钟（xAgent 任务执行需要时间）
2. 如果超过 10 分钟无响应：
   - 检查 xAgent 后端是否正常运行（`docker logs xagent_backend --tail 20`）
   - 检查 DeepSeek API Key 是否正确配置（参见部署文档 9.2 节）
3. 查看浏览器 Console 是否有网络错误（F12 → Network → 找到 `/v1/chat/completions` 请求）

### 11.3 AI 回复内容为英文

**现象**：AI 回复使用英文而非中文

**原因**：DeepSeek 模型对中文 prompt 可能回复英文。

**处理**：
1. 可在 Console → Agent → Prompt 字段中增加 "请用中文回答"
2. 或在提问时明确要求 "请用中文回复"

### 11.4 对话历史不显示

**现象**：侧边栏 "历史对话" 区域为空

**检查步骤**：
1. 确认已经成功发送过至少一条消息并收到回复
2. 刷新页面，重新查看侧边栏
3. 在 Console 中检查该用户的对话记录是否存在

### 11.5 流式输出中断

**现象**：AI 回复输出到一半就停止了

**常见原因**：
- 用户点击了 "停止" 按钮
- 网络波动导致 SSE 连接断开
- xAgent 任务执行异常

**处理**：
1. 点击 AI 气泡下方的 **"重新生成"** 图标重试
2. 如果问题反复出现，查看 xAgent 后端日志

#### 12.4.7 Quality Gate 门禁验证（P3-14 专项）

> **背景**：xAgent DAG Engine 新增输出质量门禁（Quality Gate），在 Result Analyzer 综合结果前自动检查产出是否符合 L2/L3 标准。不通过则触发重生成（最多 3 次），3 次后仍不通过则降级输出 + 标注人工介入提示。

**验证步骤**：

1. 运行场景 B（求职全链路："学员张三 Java 2年→大数据"）
2. 观察 xAgent trace event 日志中是否出现 `quality_gate_check` 事件
3. 检查以下 Quality Gate 判定项：

| # | 门禁检查项 | 最低通过标准 | 当前结果 |
| --- | --- | --- | --- |
| QG-01 | 量化指标覆盖率 | 全文 ≥ 15 个量化数字 | ☐ |
| QG-02 | 分级时间线 | ≥ 3 个时间层级 + 每操作有预计耗时 | ☐ |
| QG-03 | 具体资源引用 | ≥ 8 个具体资源引用（书名+章节/URL/练习编号） | ☐ |
| QG-04 | 结构完整性 | ≥ 6 个二级标题 + 表格/列表 | ☐ |
| QG-05 | 风险与回退 | ≥ 3 项风险（每项含概率+影响+Plan B） | ☐ |
| QG-06 | 学习方案字数 | ≥ 1500 字 | ☐ |
| QG-07 | 简历方案字数 | ≥ 800 字 | ☐ |
| QG-08 | 空泛 Anti-Pattern | 0 出现（全文搜索 Anti-Pattern 词库） | ☐ |

**Anti-Pattern 检测词库**（出现任意一个即不通过）：
```
"建议补充相关" / "建议多练习" / "建议多投递" / "可以参考网上"
/ "后续补充" / "慢慢来" / "根据情况" / "网上有很多" / "搜索一下"
/ "注意提升" / "尽量做好" / "加强"（后不跟具体手段） / "改善"（后不跟具体目标值）
```

**降级场景验证**（可选）：
1. 将 Mock Gateway 某个工具设为 `scenario=summary_only`（返回低质量数据）
2. 观察 xAgent Quality Gate 是否检测到质量问题并触发重生成
3. 验证重生成后的产物质量是否提升

> **判定规则**：QG-01 至 QG-05 任一项不通过 → P3-14 整体阻塞。QG-06/07/08 不通过 → 高优 bug。
