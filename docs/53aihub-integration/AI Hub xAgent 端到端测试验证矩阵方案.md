# AI Hub xAgent 端到端测试验证矩阵方案

版本：v1.0  
日期：2026-05-06  
范围：53AIHub 入口、xAgent 调度、Dify/Coze/自研 Agent 执行、记忆、审批、审计、KPI。

## 1. 测试目标

1. 验证 53AIHub 可以作为统一入口发起 xAgent 调度任务。
2. 验证 xAgent 可以把 53AIHub 中的 Dify/Coze/自研 Agent 当作工具调用。
3. 验证销售、教学、教研、求职四条完整业务流的成功路径、失败路径、审批路径。
4. 验证权限、PII、审计、trace、KPI 满足企业内测要求。
5. 验证系统在超时、429、Agent 禁用、文件映射失效、Planner 误选工具时可以降级和定位。

## 2. 测试环境

| 环境 | 用途 | 要求 |
| --- | --- | --- |
| local-dev | 开发联调 | 53AIHub、xAgent、本地数据库、Mock Dify/Coze |
| staging | 端到端验收 | 接真实 Dify/Coze 沙箱、钉钉/企微测试群 |
| pilot | 小范围试点 | 内部销售/助教真实使用，外发默认审批 |

基础数据：

1. 企业：`eid=1`。
2. 用户：管理员、销售、助教、教研、求职顾问、学员各 1 个。
3. 用户组：销售组、教学组、教研组、求职组、学员组。
4. Agent：每条业务流至少准备 3 个可用 Agent。
5. 文件：简历 PDF/DOCX、作业代码、课程录音、面试录音、小红书链接样本。
6. Mock 外部系统：CRM、CareerMagic、CareerOS、钉钉/企微。

## 8.1 输出可执行性验证（核心质量维度）

> **设计原则**（详见需求设计文档 5.5 节、`AI Hub xAgent 系统提示词工程与输出质量保障方案.md`）：系统输出必须是"可直接执行的方案"，而非"摘要性总结"。最低质量门槛为 **L2（可执行级）**，关键交付物应达到 L3（闭环方案级）。
> **质量保障机制**：三层保障体系（Schema 约束层 → Prompt 注入层 → Quality Gate 门禁层），方法论参考 Tencent Cloud #2668186 "生产级 Multi-Agent Harness"。

### 8.1.1 可执行性等级判定标准

| 等级 | 名称 | 判定依据 |
| --- | --- | --- |
| L0 | 摘要级 | 仅概括方向，无可操作步骤。例："建议补充大数据技能" |
| L1 | 要点级 | 列出要点但缺少具体操作指令、时间线、量化标准 |
| L2 | 可执行级 | 每个产出包含：具体步骤 + 时间安排 + 量化目标 + 资源引用 + 风险提示 |
| L3 | 闭环方案级 | L2 + 前置条件检查 + 交付物清单 + 验收标准 + 回退路径 |

**硬性门禁**：全部四条业务流的核心产出物必须达到 L2，综合方案必须达到 L3。违反此标准等同于发布阻塞。

### 8.1.2 销售流可执行性验证

| ID | 产出物 | 验证项 | 最低等级 | 判定方法 |
| --- | --- | --- | --- | --- |

### 8.1.7 Quality Gate 机制验证（新增）

> **设计来源**：需求设计文档 5.5.5 节"三层输出质量保障体系"中的 Layer 3（Result Analyzer Quality Gate）。

| ID | 验证项 | 触发条件 | 预期结果 | 通过标准 |
| --- | --- | --- | --- | --- |
| QG-001 | Quality Gate 正常通过 | 所有 Step Agent 返回 L2 以上质量的输出 | `quality_gate_check` trace event → `pass=true`，不触发重生成 | 最终输出 ≥ L2 |
| QG-002 | 空泛输出检测并重生成 | Mock 工具返回 `scenario=summary_only`（含"建议补充相关技能"等空泛语句） | Quality Gate 检测到 Anti-Pattern → `pass=false` → 触发重生成 → 重生成后质量达标 | 重生成后输出 ≥ L2 |
| QG-003 | 重试上限保护 | 某 Step Agent 持续返回低质量输出 | 第 1 次重生成（不达标）→ 第 2 次（不达标）→ 第 3 次（不达标）→ 降级标注 | 最大重试 3 次，降级时有 `⚠️ 人工介入` 标注 |
| QG-004 | 量化指标不足检测 | 输出中量化数字 < 10 个 | Quality Gate → `pass=false` → `failed_items=["量化指标覆盖率"]` → 重生成要求补数字 | 重生成后 ≥ 15 个量化数字 |
| QG-005 | 时间线缺失检测 | 输出含"后续补充"且无时间层级 | Quality Gate → `pass=false` → `failed_items=["时间线完整性"]` → 重生成 | 重生成后 ≥ 3 个时间层级 |
| QG-006 | 资源引用不足检测 | 输出含"参考网上教程"且无具体引用 | Quality Gate → `pass=false` → `failed_items=["资源引用充分性"]` → 重生成 | 重生成后 ≥ 8 个具体引用 |
| QG-007 | 结构不完整检测 | 输出为连续纯段落文字，无标题/表格/列表 | Quality Gate → `pass=false` → `failed_items=["结构化输出"]` → 重生成 | 重生成后 ≥ 6 个二级标题 |
| QG-008 | 风险提示缺失检测 | 综合方案仅正面建议，无风险分析 | Quality Gate → `pass=false` → `failed_items=["风险提示"]` → 重生成 | 重生成后 ≥ 3 项风险 |
| QG-009 | xAgent trace 完整性 | 任意任务执行 | trace event 中可查询到 `quality_gate_check_attempt`（含 pass/fail/reason/retry_count） | 每次 Quality Gate 检查都有 trace event |
| QG-010 | 跨版本回归 | 升级 System Prompt 或模型后重新运行验证场景 | 使用 QA 录制的固定输入（8.1 节求职全链路），对比新旧版本输出质量 | 质量不退化（量化指标数、字数、结构化程度 ≥ 基线） |

> **背景说明**：QG-001 至 QG-008 依赖于 xAgent 后端代码修改（`result_analyzer.py`、`dag_plan_execute.py`），实现进度见 `AI Hub xAgent 集成开发对接计划.md` §8.2"输出质量门禁（Output Quality Gate）实施专项"。
